# round_N レビュー依頼プロンプト（テンプレート）

`pending_review/round_N.md` の中身をコピペした**直後**に、続けて以下を貼り付けてください。

---

あなたは研究ループ（hypothesis → verify(SymPy) → 批評A/B → 第三の意見 → 一時停止）における
「人間側の最終レビュアー」です。上に貼った`round_N.md`の内容について、以下の順で回答してください。

## 1. 検証結果そのものを疑う
`verify_ok`や批評A/Bの「妥当／要修正」判定を鵜呑みにしないでください。
特に以下を必ず自分でチェックしてください：
- SymPyコードは実際に書かれた通りに動くか（`lhs`/`rhs`が本当に未定義か、それとも
  verify_nodeのバグ・変数名の取り違えで誤って`verify_ok=False`になっている可能性はないか）
- 批評A・批評Bが検証結果に対して下した判断は、コードの実態と整合しているか
- 二人のレビューモデルの意見が食い違っている場合、どちらの言い分が数式的に正しいかをあなた自身の計算で決着させる

## 2. 導出の数学的妥当性を独立に確認
命題・導出を最初から自分で追い、以下の形式で説明してください（私が高次漸近理論の初学者のため）：
- 各主要な数式について「①式全体が何を主張しているか ②各記号の定義 ③直感的な意味」の3点セット
- 可能なら高校〜大学1年レベルのアナロジーを添える
- 暗黙の仮定・破綻するケース（批評が挙げたもの含む）が本質的にどこから来ているかを直感的に説明

## 3. 文献との整合性を確認する（Web検索で実際に調べること）
批評A/B・第三の意見はどの文献とも突き合わせていません。この命題・導出のテーマ・キーワード
でWeb検索し、関連しそうな論文を実際に探し出した上で、
この命題・導出がそれらと関係するか、矛盾しないかを確認してください。

- **記憶だけで断定しないでください。** 必ずWeb検索でその論文（タイトル・著者・年）を調べ、
  要旨や結果を確認してから照合してください。
- 検索で見つけた内容と、この命題・導出の主張が「一致する／一般化・特殊化の関係にある／矛盾する」
  のどれに当たるかを、検索結果に基づいて判定してください
- 論文の原文を確認できない場合（プレプリントが見つからない、要旨だけで詳細が不明など）は、
  分かった範囲を書いた上で「要出典確認（原文未確認）」と正直に書き、推測で断定しない
- 検索してもそれらしい文献が見当たらない場合も「関連文献なし（検索で未確認）」と書く
- どの論文を参照したかを、回答の中で明示してください（次節の出力にも反映させること）

## 4. 次の一手を明確に指示する
以下の形式で、次の`hypothesis_node`に渡す指示を書いてください（この部分が
`human_feedback`としてそのまま次ラウンドのプロンプトに挿入されます）：

> **次の一手の指示：** （1〜3文。「〜を修正せよ」「〜の方向へ一般化せよ」等、次のLLMが
> そのまま動けるレベルの具体性で）

## 5. 出力全体の構成
最後に、`round_N_claude.md`としてそのまま保存できるよう、回答全体を以下の見出し構成で
まとめ直してください（`write_review_to_memory.py`が最初の1行を要約として自動抽出するため、
**冒頭1行に次の一手の要点を書く**こと）：

```
# Round N Claudeレビュー

## 検証結果の裁定
（verify_okや批評の食い違いに対するあなたの判断と根拠）

## 数式・導出の解説（初学者向け）
（3点セット形式の説明）

## 妥当性の総合評価
（この命題は採用可／要修正可／却下、を明言）

## 文献との関係（Web検索で確認済み）
（3節の内容。参照した論文名を明記。検索結果を引用する場合は要約に留め、原文の長文コピペはしないこと。
未確認の場合は「要出典確認（原文未確認）」と正直に書く）

## 次の一手の指示
（4節の内容をそのまま）
```

---

## なぜこの形にしたか（設計意図）

- **検証結果を疑わせる**：round_1の実例で、批評Bが「verify_nodeの判定はコードと矛盾している」
  と指摘していました。verify_ok自体がバグで誤判定している可能性があるため、あなたが唯一の
  「人間の目」として最終チェックする必要があります。
- **3点セット指定**：これは以前あなたが指定した説明形式をそのまま組み込んでいます。
- **冒頭1行**：`write_review_to_memory.py`が`claude_review.strip().splitlines()[0][:150]`を
  ログの要約として機械的に抜き出すため、ここが空欄や前置きだと長期ログが空疎になります。
- **文献照合はWeb検索必須**：LLMの「記憶」だけで論文の内容を照合すると、もっともらしいが
  実在しない対応関係をでっち上げるリスクがあります。claude.aiのWeb検索機能を使わせることで、
  実際の論文の要旨・結果に基づいた照合にし、断定できない場合は正直に「要出典確認」と書かせています。
- **「次の一手」を独立節にする**：`human_feedback`は次のプロンプトにそのまま挿入されるだけなので、
  あなたの感想文ではなく、次のLLMへの命令文として書く必要があります。
